### 乱码前后导航夹具（API 36 Release 已执行）

生成确定性夹具与预期清单：

```bash
rtk ./gradlew --no-daemon :core:generateMalformedNavigationFixture
rtk sha256sum core/build/device-smoke/jingdu-malformed-navigation.txt
```

生成结果位于 `android-prototype/core/build/device-smoke/`。源文件固定为 269,521 字节，SHA-256 应为 `47a40a53ca8aed70bfa9cb7c9719d7fa800aaf38d9b07f0bb7765db16a495c68`；它包含 130 个单字节非法 UTF-8 序列，位置跨越三个约 128K 的阅读窗口。`jingdu-malformed-navigation.expected.txt` 保存全部预期偏移，其中前 128 项为可导航位置，最后两项明确标记为 `unretained`。

设备到位后执行：

1. 安装本文“最新构建”对应 APK，把生成的 TXT 放入设备 Downloads；
2. 在导入编码中选择 `UTF-8`，经真实 `ACTION_OPEN_DOCUMENT` 选择该文件；
3. 核对摘要显示完整替换数 130、首处源字节 2091，并提示仅保留前 128 处定位；
4. 首次点击“下一处乱码”应显示 `1/128`、源字节 2091、原文位置 2071；继续导航到第 64 和 128 处，分别核对清单并确认跨窗口载入无崩溃、无自动滚动/TTS 幽灵恢复；
5. 到第 128 处后“下一处乱码”禁用；点击“上一处乱码”应回到第 127 处，129/130 不得伪装成可定位项；
6. 新建并应用位于所有异常之前的单一净读规则 `净读→净`，再次从第 1 处导航；原文位置仍为 2071，当前视图位置应为 2070，以验证投影映射；
7. 强制停止并冷启动，确认 profile v4 恢复完整计数与 128 个位置，导航游标从未选择状态重新开始；
8. 开启 TalkBack，核对两个按钮名称、禁用边界和状态更新，不把技术 revision 读入正文描述。

API 36 Release 已经真实 SAF 流程完成步骤 1–3，并验证第一次跳转正文为 `ERROR-001=>�<=ERROR`、正文锚点 2060；私有规范化副本对应字节为 `3d 3e ef bf bd 3c 3d`，证明替换符后的合法 `<` 未再丢失。外部源文件设备端与主机端 SHA-256 均保持 `47a40a…`。步骤 4–8 的 64/128 边界、净读映射和 TalkBack 完整矩阵仍为真机待验。

根因是 Android ICU 在 `REPORT` 错误返回时已把 `ByteBuffer.position()` 推进到错误范围末端，而桌面 JDK 保留在错误范围起点；旧循环再次按 `result.length()` 前移会跳过合法后继字节。当前实现使用独立探针校准具体运行时语义。主机 `CorePrototypeTest` 42 场景通过，API 36 instrumentation 对 UTF-8、GB18030、GBK、GB2312、Big5、UTF-16LE、UTF-16BE 七编码均验证“只跳过平台报告的错误范围”。

最新 Release 基础自动滚动 smoke：

- 启动位置 2060，自动滚动关闭；
- 约 2.5 秒后位置 2160，自动滚动开启；

最新构建已加入 8–120 dp/秒系统滑杆、拖动即时预览、松手同步记忆、键盘/TalkBack 非触摸调节持久化和失败回滚；触摸后可保持暂停或在 3/5/10 秒后恢复，并可选择仅在滚动时保持屏幕常亮。恢复倒计时绑定 revision 和锚点；显式停止、再次触摸、跳转、TTS 及进入后台均取消。共享核心证明 60/90/120Hz 在 1 秒内积分位移一致，500ms 异常停顿按 100ms 截断，并覆盖恢复状态机的一次性触发与失效。真实多刷新率速度、触摸暂停小于 100ms、倒计时/常亮系统行为、重启恢复、文末停止与 30 分钟耐久仍为 `device-pending`。

### 最新增量（构建通过，设备待验）

- 导入编码新增 Big5：繁体常用字证据显著领先时自动选择；与 GB18030 同时严格可解但证据不足时保守回退。64KiB 样本窗口截断允许最多 3 个未完成尾字节，真实 EOF 残缺进入损坏字节替换路径；核心以枚举区分 Big5 启发式、旧编码歧义和损坏字节，Android 独立状态行持续给出切换编码重导与核对正文提示，重复导入和同源重解码确认不会覆盖本次告警；
- 编码置信度、自动/手动来源和告警以 `bookId + baseRevision` 命名的 CRC 原子 profile 保存；恢复书籍时严格核对内容绑定，缺失按旧书库降级，损坏显示重建提示但不阻断正文；重解码清理旧 revision，删除副本纳入 pending 日志续作清理；
- 全文件使用单遍 `REPORT` 恢复解码：每个 malformed/unmappable 序列写一个替换符，完整统计事件数并仅保留前 128 个零基源字节偏移/规范化原文字符锚点对，字节偏移包含 BOM、字符锚点包含 CR/LF 规范化；Android 在任意自动/手动编码摘要后显示精确统计与保留上限，通过“上一处/下一处乱码”顺序导航；净读视图逐个映射到活动 revision，完整索引未就绪且目标不在当前窗口时明确等待；profile v4 跨重启保存并继续读取 v1/v2/v3；
- ReaderSurface 支持长按选择中文单字/拉丁词、拖动扩选、跨行高亮和复制/搜索/创建规则浮动菜单；选区端点不拆 UTF-16 代理对，空白规则和超限字段被拒绝；

## 已知偏差

1. 系统 `/usr/bin/adb` 为 1.0.39，SDK ADB 为 1.0.41；模拟器内部调用旧 ADB 造成 server 反复切换和警告，但最终安装与 smoke 成功。
2. AGP 9.0.1 读取最新 SDK repository XML 时报告仅理解 XML v3、遇到 v4；构建和 lint 成功，后续升级 AGP/Gradle 后复核。
3. `startActivityForResult` 和部分 View API 存在弃用提示；W0 为无 AndroidX 原型，正式工程应迁移到 Activity Result API。
